# fix-sensenova-429-quota-retry 设计

## Context

现状链路（详见 proposal.md「Why」）：`stream()` 以 per-key 并发闸（默认 1）串行化后直发 `{apiBase}/chat/completions`；429 一律映射为 `RATE_LIMIT`（不分类、不轮换、不冷却），`providerRetryPolicy` 声明 `maxRetries: 1000`、退避上限 3000ms（`src/adapter.ts` 的 `PROVIDER_RETRY_AFTER_CAP_MS`）；生成请求无任何超时。

D0/D1 实测补充两条新事实（除 proposal 已列外）：

- **TPM 按模型分档且差异极大**：`deepseek-v4-flash` 在单 key 上约 1.4 万 tokens/分钟即触发 `429001`；`deepseek-v4-pro` / `sensenova-6.8-flash-lite` 灌到 19.5 万 / 44.5 万 tokens 均未触顶。多会话大上下文（单次 7k–55k input）在 flash 档极易触发 TPM 耗尽。
- **「per-key prompt 缓存」缺乏高价值证据**：14.2k tokens 相同 prompt 同 key 复用仅快约 13%（1443ms→1254ms），响应 usage 无 `cached_tokens` 字段；跨 key 首打慢 2.7×（3710ms，单样本，噪声存疑）。即使缓存存在，一次切换的冷启代价（约 +0.1s~2.4s）也远小于轮换所避免的配额等待（15s/60s 量级）。

## Goals / Non-Goals

**Goals:**

- 429 处理与真实配额形态对齐：按错误体 `error.code` 分类，配额类给出分钟级退避下限。
- 重试预算有限化：持续限流时失败尽早可见，消灭「1000 次 × 3 秒」的无限重试观感。
- 消除挂起卡死路径：请求建立、流读取、排队等待三个阶段都有超时保护并释放并发额度。
- 提供可选的配额类 429 粘性换 key 能力（默认关闭），并保持「429 永不冷却/禁用账号」不变。

**Non-Goals:**

- 不改变 401 禁用轮换语义与账号状态机。
- 不实现客户端配额桶预测（不本地记账 RPM/TPM 余额，只按服务端反馈退避——桶参数实测会漂移，客户端预测易失真）。
- 不修改设置页既有字段结构与 Models 卡片（仅新增一个高级区开关）。

## Decisions

### D1: 429 按 `error.code` 二分类，未识别 code 归非配额类

配额类 = `code === 8`（`rps/rpm exhausted`）或 `code === 429001`（`inference tpm exhausted`）；其余（含无 code）归非配额类，维持现行短退避语义。备选方案「按 message 正则分类」被否：message 措辞随版本漂移（实测同 code 8 出现过 `rps exhausted` 与 `rpm exhausted` 两种），code 更稳定。「按官方错误表的 `type` 分类」同样被否：官方表将 429 统一标为 `quota_exceeded_error`，但实测 `429001` 的 `type` 实为 `invalid_request_error`（09-02 与 09-04 两次现场一致），按 type 分类会漏掉 TPM 类。

### D2: 配额类退避——code 8 固定 15000ms，429001 分级探测 3/5/10/15s 递增封顶、成功归零

依据：速率桶补充 ≈1 个/14 秒（15s 覆盖一个完整补充周期），code 8 固定 15s；429001 为 per-key 推理 token 限速（2026-09-04 实测 key A 30k 请求 429001、key B 同刻通过；官方文档将 429 统一标注 quota_exceeded_error 建议指数退避，未公开数值），恢复时间不定——**固定长下限（60s/180s）会把会话干锁在死等里**，故采用分级探测：连续命中档位 3s→5s→10s→15s 封顶，任一成功或换 key 归零回到 3s，恢复第一时间接上；开 `quotaRotation` 时优先换 key（实测换 key 秒级成功）。实测 429 响应无 `Retry-After` 头，但保留「响应携带且大于当前档位时采用 `Retry-After`」的规则以兼容网关行为变化；采用值整体封顶 300000ms。实现为 `providerRetryAfterMs` 附加在 `RATE_LIMIT` 错误上，交宿主重试层执行。

### D3: `providerRetryPolicy` 收敛为 `maxRetries: 10`、退避单次上限 60000ms

`maxRetries` 取 10：配合 429001 分级探测（最长 15s/档）与 code 8 固定 15s，10 次重试预算已覆盖可预期的恢复窗口，超出则应显式失败。本地退避单次上限取 60000ms：为无 `providerRetryAfterMs` 指导时的本地指数退避封顶；TPM 分级档经 `providerRetryAfterMs` 通道单独下发（宿主按该指导延迟）。备选「维持 1000 次但延长上限」被否：重试预算不收敛时 UI 仍呈「无限重试」，违背本变更目标。

### D4: 三段超时——连接/首字节 45s、流空闲 60s、排队 60s，超时以可重试 `TIMEOUT` 结束并释放额度

- 连接/首字节：`fetch` 叠加 `AbortSignal.timeout(45s)` 与宿主 `signal` 组合（实测传输挂起 ≈1/5 且无 RST，45s 覆盖正常大 prompt 建连+首包）。
- 流空闲：SSE 读取循环以「距上一事件 ≥60s」判定停摆（任何 chunk/事件重置计时）；思考型模型长思考期间有心跳/空事件则自然重置，若确无事件则属于停摆，按可重试超时处理。
- 排队：`KeyedConcurrencyGate.acquire` 增加 `queueTimeoutMs`（默认 60000ms），排队超时以可重试错误 reject（不占额度），交宿主退避后重试。
- 三者统一映射 `TIMEOUT` 错误码（在宿主默认可重试集合内），`finally` 释放额度路径复用现有 release 逻辑。

### D5: 可选「配额类 429 粘性换 key」——新增设置 `quotaRotation`（默认 `false`）

- 语义：开启后，仅配额类 429 触发切换到下一把可用 key，且**粘住新 key**（同一会话后续请求继续用新 key，直到它也被配额类 429 拒绝再依序切换，环回则退回等待退避）；非配额类 429、401 路径行为不变；任何 429 仍不冷却、不禁用账号。
- 默认关闭：尊重既有「429 不换 key」决策；缓存实测代价小（见 Context），但样本有限（跨 key 仅 1 例），保守起见由用户显式开启。
- 依据：配额桶与 TPM 池均实测为 per-key 隔离，换 key 可立即获得新桶；flash 档 TPM 极小（约 1.4 万 tokens/分钟）时收益尤其明显。
- 设置页：高级设置折叠区新增开关「配额类 429 换 key」，默认关，文案说明「仅限流耗尽时切换到下一把 key；密钥失效（401）行为不变」。
- 备选「随机/每请求轮换」被否：会在两把 key 间乒乓，缓存冷启与 TPM 双侧计费被放大；粘性轮换把代价收敛为每次切换一次冷启。

### D6: 桶参数常量化并注明实测日期，不做设置项

15s/60s 下限、45s/60s/60s 超时为常量（含中文注释标注「2026-09-04 实测」）。理由：SenseNova 未公开配额文档，参数可能漂移；暴露为设置项会让用户背上调参负担，等漂移证据出现再评估。

## Risks / Trade-offs

- [配额参数漂移（桶容量/补充速率/TPM 档位变化）] → 退避下限只是「下限」，宿主指数退避仍会自然增长；`debug_quota_probe*.mjs` 留仓可随时复测定参。
- [maxRetries 收敛后，长时配额故障更早暴露给用户] → 属预期目标（显式失败优于静默风暴）；错误信息保留「请求被限流」语义便于用户理解。
- [流空闲 60s 误杀超长静默思考（无心跳事件）的模型] → 判定基于「无任何 SSE 事件」，实测渠道在思考期有空事件/心跳；若出现误杀，`TIMEOUT` 可重试且常量可调。
- [粘性轮换在双 key 都饱和时退化] → 环回后不再切换，退回 D2 退避下限等待；不会放大请求量。
- [跨 key 缓存证据样本弱（n=1）] → 默认关闭 + 开关文案明示收益与代价；后续可复跑 `debug_cache_probe.mjs` 补样本。
- [粘性/环回状态为进程内 Map/Set 且无淘汰（单条目百字节级）；401 轮换不更新粘性指针——粘住 key 被禁用时每次请求多一轮 401 往返后经轮换自愈] → 已知低风险限制（critic 定向复核确认不阻塞），生命周期绑定适配器进程；单进程会话量极大时再评估 LRU/TTL。

## Migration Plan

无数据迁移。发布即生效（新策略随插件加载热生效）；回滚即回退插件版本。默认行为变化仅两处且均为修复目标：重试预算 1000→10、退避上限 3s→60s；`quotaRotation` 默认值保持现状语义（关闭）。
